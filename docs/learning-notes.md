# 学習メモ

## Pydantic Settingsの継承

`BaseSettings`を継承したクラスでは、型注釈で設定項目を定義し、環境変数や指定ファイルから値を読み込んで検証できます。手動で各設定元を読み込んで変換する方法もありますが、複数の設定元と型検証をまとめるために使います。

## Pydantic `BaseModel`

`BaseModel`を継承すると、渡されたデータを型に合わせて検証するモデルを作れます。`BaseSettings`と違い環境変数や設定ファイルは読み込まず、データを直接渡して使います。設定元からの読み込みが不要な例やデータに使います。

## `SettingsConfigDict`と`model_config`

`SettingsConfigDict(...)`は、`BaseSettings`の読み込み方や検証ルールを`model_config`に指定するための型付き設定です。通常の辞書でも設定できますが、設定項目の型補助が得られるためこの書き方を使います。

## 型注釈と`Field`

型注釈は設定値の型を示します。`Field(...)`は既定値や正の値などの制約を追加します。追加条件がない項目は型注釈だけで定義できます。

## デコレータとフィールド検証

`@field_validator(...)`は関数をPydanticの項目検証として登録します。デコレータを使わない形は`check = field_validator(...)(check)`です。設定を作る時に自動で検査を実行するために使います。

`@classmethod`はクラスメソッドにするデコレータで、`method = classmethod(method)`と同じ意味です。設定インスタンスを作る前の検証で、インスタンスではなく設定クラスを`cls`として受け取るために使います。

## `if __name__ == "__main__"`

`if __name__ == "__main__":`は、Pythonファイルを直接実行したときだけ、その中の処理を実行します。別のファイルからimportした場合は`__name__`がモジュール名になるため、ブロック内は実行されません。テスト対象のクラスや関数をimport時に動かさず、直接実行用のデモも同じファイルに置くために使います。条件を使わずに関数呼び出しをファイル末尾へ書くと、importしたときにも実行されます。
